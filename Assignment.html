A. Binary min-heap

Use the supplied std::vector<int> data_. Maintain data_[(i - 1) / 2] <= data_[i] for every i > 0. The root is the minimum; the array need not be sorted. Negative values and duplicates are valid.

Method to implementRequirement
build(values)Replace the contents and build bottom-up in O(n). An empty input clears the heap.
push(value)Insert one integer and sift upward; preserve existing values.
pop()Remove and return the minimum; replace the root with the last value and repair downward.
top()Return the minimum without changing the heap, in O(1).
sift_up, sift_downImplement the private repair helpers; choose the smaller child when moving downward.

top() and pop() on an empty heap must throw std::out_of_range without changing it; choose any exception message. Heap repair costs O(log n). Vector growth makes push amortized O(log n). Use vector storage and swaps; do not use std::priority_queue, STL heap algorithms, or sorting. Avoid unsigned underflow when iterating backward with std::size_t.

Commands: BUILD n v1 ... vn (nonnegative count; all values on the same line), PUSH value, TOP, POP, SIZE, EMPTY, PRINT, CLEAR, HELP, QUIT. TOP/POP print the value; SIZE prints the count; EMPTY prints true/false. PRINT shows the space-separated heap array, or a blank line if empty; valid layouts can differ.

Program input:

BUILD 5 9 4 7 1 0
TOP
PUSH -2
POP
TOP
QUIT

Expected output:

0
-2
0

Check empty/single-element heaps, duplicates, negatives, rebuilding, and interleaved pushes/pops. Repeated popping must produce nondecreasing values. Top-K is not part of this assignment.

B. Chained hash table

Map std::string keys to int values using the supplied std::vector<std::list<Entry>> with exactly seven buckets. size_ counts entries, not buckets.

Method to implementRequirement
bucket_index(key)Start at h = 0; for each unsigned byte c, set h = (31 * h + c) % 7. Return h.
put(key, value)Update an existing key without changing the size; otherwise append an entry to its chain and increment the size.
find(key)Return its value as std::optional<int>, or std::nullopt if absent. Do not modify the table.
erase(key)Remove only that key, decrement the size, and return true; if absent, return false without changes.

Colliding keys are different entries: compare complete keys within a bucket. The empty key is valid (bucket 0); all integer values, including −1, are valid. Do not use a sentinel integer for missing values. Use the supplied lists, not std::map, std::unordered_map, or sets. No resizing or rehashing is required. Keys a, h, and o all map to bucket 6.

Commands: PUT key value, FIND key (prints value or NOT_FOUND), ERASE key (prints true/false), BUCKET key (prints index), SIZE, EMPTY, CLEAR, HELP, QUIT.

Keys and log records use std::quoted: a bare word or double-quoted text, including "" for empty text. For example, PUT "first name" 12. Within quotes, \" and \\ escape a quote and backslash. C-style \n/\0 do not become control bytes; use C++ API tests for binary strings.

Program input:

PUT a 10
PUT h 20
PUT o 30
PUT h 25
FIND h
ERASE h
FIND h
FIND o
SIZE
QUIT

Expected output:

25
true
NOT_FOUND
30
2

Check collisions, updates, missing/empty keys, and deletion at the beginning, middle, and end of a chain. Surviving entries must remain accessible.

C. Log hash chain — optional extra credit

Use the provided lab::crypto::hash_record(previous, record) helper:

d0 = 32 zero bytes
di = SHA256(d(i−1) || record_i)

Concatenate the 32 raw digest bytes and exact record bytes, not a hexadecimal digest string. Add no separators, newline, or terminating NUL. Records are std::string; textual records use UTF-8. Empty records and embedded NUL bytes are valid. The initial digest is not SHA-256 of an empty string.

Method to implementRequirement
append(record)Hash the previous digest and new record, then store both in a LogEntry. Use initial_digest() before the first record.
final_digest()Return the last digest, or initial_digest() if empty.
verify(entries, trusted_final)Recompute in order from the initial digest. Check every stored digest and the final result against the trusted anchor; return false on any mismatch. An empty chain passes only with the zero initial anchor.

Commands: APPEND record, DIGEST (prints 64 hex characters), SAVE, VERIFY, CHECK_EDIT index record, SIZE, EMPTY, CLEAR, HELP, QUIT.

SAVE silently stores the current final digest in memory; it writes no file. VERIFY and CHECK_EDIT require this saved anchor and print true/false. CHECK_EDIT changes a zero-based record in a temporary copy, leaving the original unchanged. APPEND does not update the anchor: verification fails after appending until you deliberately save again. CLEAR clears both log and anchor.

Program input:

APPEND "Alice pays Bob 10"
APPEND "Bob pays Carol 4"
SAVE
VERIFY
CHECK_EDIT 0 "Alice pays Bob 100"
VERIFY
QUIT

Expected output:

true
false
true

Check changed records/digests, deletion, reordering, and rewritten chains with all later digests recomputed. A rewritten chain must fail against the original trusted final digest. Keep that anchor separately from editable history: the chain detects changes against it, but does not prevent edits, encrypt records, or authenticate the writer.
